# Firebase Configuration Overview

This document explains the `firebase.json` configuration file for the Dark Productivity Suite.

## File Location

`firebase.json` - Root of the project

## Configuration Sections

### 1. Firestore Database

```json
"firestore": {
  "rules": "firestore.rules",
  "indexes": "firestore.indexes.json"
}
```

**Purpose**: Configures Firestore database security and performance

- **`firestore.rules`**: Security rules that protect user data
  - Users can only access their own data
  - Validates data structure on writes
  - Prevents unauthorized access

- **`firestore.indexes.json`**: Database indexes for query optimization
  - Improves query performance
  - Required for complex queries
  - Auto-generated by Firebase

### 2. Hosting

```json
"hosting": {
  "public": "dist",
  "ignore": [...],
  "rewrites": [...],
  "headers": [...]
}
```

**Purpose**: Configures Firebase Hosting for the web application

#### Public Directory
- **`"public": "dist"`**: Serves files from the Vite build output directory

#### Ignore Patterns
Excludes files from deployment:
- `firebase.json` - Configuration file
- `**/.*` - Hidden files (e.g., `.git`, `.env`)
- `**/node_modules/**` - Dependencies

#### Rewrites (SPA Routing)
```json
"rewrites": [
  {
    "source": "**",
    "destination": "/index.html"
  }
]
```

**Purpose**: Enables client-side routing for Single Page Application
- All routes redirect to `index.html`
- React Router handles navigation
- Prevents 404 errors on page refresh

#### Caching Headers

**Static Assets** (1 year cache):
```json
"source": "**/*.@(js|css|woff|woff2|ttf|eot|svg|png|jpg|jpeg|gif|ico)",
"headers": [{
  "key": "Cache-Control",
  "value": "public, max-age=31536000, immutable"
}]
```

**Benefits**:
- Aggressive caching for versioned assets
- Reduces bandwidth usage
- Improves load times for returning visitors
- `immutable` flag tells browsers file will never change

**HTML Files** (no cache):
```json
"source": "**/*.html",
"headers": [{
  "key": "Cache-Control",
  "value": "public, max-age=0, must-revalidate"
}]
```

**Benefits**:
- Always serves fresh HTML
- Ensures users get latest app version
- Allows instant updates without cache clearing

### 3. Cloud Storage

```json
"storage": {
  "rules": "storage.rules"
}
```

**Purpose**: Configures Cloud Storage security rules

- **`storage.rules`**: Controls file upload/download permissions
  - Users can only access their own files
  - Validates file types and sizes
  - Prevents unauthorized access

## Deployment Commands

### Deploy Everything
```bash
firebase deploy
```

### Deploy Specific Services
```bash
# Hosting only
firebase deploy --only hosting

# Firestore rules and indexes
firebase deploy --only firestore

# Storage rules
firebase deploy --only storage

# Multiple services
firebase deploy --only hosting,firestore,storage
```

## Performance Optimizations

### Caching Strategy

1. **Static Assets** (JS, CSS, fonts, images):
   - Cached for 1 year
   - Vite generates unique filenames with content hashes
   - Old versions automatically invalidated
   - Example: `main-abc123.js` → `main-def456.js`

2. **HTML Files**:
   - Never cached
   - Always fetches latest version
   - References latest hashed assets

### Result
- Fast initial load (cached assets)
- Instant updates (fresh HTML)
- Minimal bandwidth usage
- Optimal user experience

## Security Features

### Firestore Rules
- Row-level security (users can only access their own data)
- Data validation on writes
- Protection against unauthorized access

### Storage Rules
- File-level security
- User-specific folders
- File type and size validation

### Hosting Security
- HTTPS enforced by default
- Automatic SSL certificate provisioning
- DDoS protection included

## Common Tasks

### Update Security Rules
1. Edit `firestore.rules` or `storage.rules`
2. Deploy: `firebase deploy --only firestore,storage`

### Update Hosting Configuration
1. Edit `firebase.json` hosting section
2. Rebuild: `npm run build`
3. Deploy: `firebase deploy --only hosting`

### Add Database Indexes
1. Firebase Console will suggest indexes when needed
2. Copy suggested index to `firestore.indexes.json`
3. Deploy: `firebase deploy --only firestore:indexes`

## Troubleshooting

### "Permission denied" errors
- Check Firestore/Storage rules
- Ensure user is authenticated
- Verify user ID matches in rules

### "Index required" errors
- Firebase Console will show required index
- Add to `firestore.indexes.json`
- Deploy indexes

### Caching issues
- HTML is never cached (always fresh)
- Clear browser cache for testing
- Use incognito mode to test fresh loads
